# Updates and release packages

Briefcase ServerApp owns Windows server updates. It checks GitHub's latest stable Briefcase release and each configured HTTPS mod catalog, compares installed versions, downloads archives, verifies SHA-256 digests, and installs updates while the server is stopped. The app may apply known pending updates before it starts or restarts a server. The native runtime, proxy, injector, and UE4SS perform no network update work at startup.

`VERSION` at this repository's root is the framework version source. The Windows server release asset is named `BriefcaseNative-Server-windows-x64-MAJOR.MINOR.PATCH.zip`. ServerApp obtains the asset's SHA-256 digest from GitHub, then validates the ZIP's `Package.json`, the target game executable hash, every file's size and hash, and allowed paths before replacing files. Marked files such as `ue4ss/Mods/mods.txt` are preserved. The app stages files and backs up those it replaces; an installation error triggers rollback, and an interrupted transaction is recovered before the next launch. A stopped server is required.

Mods are described by ServerApp marketplace catalogs. The new `schemaVersion: 2` format identifies each mod by a lowercase folder ID under `ue4ss/Mods`, with a version, archive URL and SHA-256, author, optional logo URL and SHA-256, and optional documentation and community URLs. ServerApp stores the catalog URL and installed version in `.serverapp-install.json` inside each managed mod. Its catalog cache supports offline display and HTTP revalidation. The app preserves an existing `Data/config.json` during an update. Existing schema 1 catalogs remain readable while publishers migrate.

ServerApp owns managed server starts and restarts. The native restart helper and update coordinator are no longer packaged with Briefcase. The proxy does not call them on startup. ServerApp disables the active `Briefcase/updater.json` before launch to prevent an older installed proxy from starting its own update path.

Direct Shipping launches through an enabled `version.dll` still initialize Briefcase, early mod helpers, and UE4SS before game entry, but do not check for updates. ServerApp renames `version.dll` to `version.dll.disabled` before its managed launch and tells the user. Direct Steam launches are then unmodded. ServerApp keeps `Briefcase.ServerInjector.exe` and `Briefcase.ServerBootstrap.dll` in its own `Native` subfolder and starts Shipping headless without putting those files in the Briefcase release or the game directory. A child-process marker prevents a proxy that unexpectedly remains present from initializing the runtime twice. ServerApp also prepares `sb.DisableEAC=1` in `DeceiveInc/Saved/Config/WindowsServer/Engine.ini` before launch.

Linux is not currently distributed by the Windows release workflow. The experimental Linux launcher no longer checks for releases when it starts or restarts the server; a future Linux management path will own its updates.

`.github/workflows/release.yml` publishes a new framework release when `VERSION` changes on `main`, or by manual workflow dispatch. The publication validates the package contents and release digests. No separate `.sha256` asset is needed because GitHub publishes each asset digest in its release API.
